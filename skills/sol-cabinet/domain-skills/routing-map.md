# Domain Skills 路由

先由 Sol Cabinet 锁定目标、边界和唯一执行路径，再调用当前环境中可用的最小底层能力集。平台官方 Skill、工具、插件或渲染器名称只代表实现接口，不是第二个上层工作流；不要因为文件类型出现就加载全部 Office 能力，也不要让同类能力各自规划、各自检查一遍。

| 目标 | 底层原子能力 | Cabinet 只补充 |
|---|---|---|
| Word 创建、修订、批注、红线 | 当前平台原生文档读取／编辑／创建／渲染／技术校验能力 | [Office](office-delivery.md)；需要正式写作时再读[正式写作](formal-writing.md) |
| Excel、CSV、台账、公式 | 当前平台原生表格读取／编辑／公式／技术校验能力 | 仅在业务或数据规则需要时读[台账与数据](ledger-data.md) |
| PowerPoint/Google Slides | 当前平台原生演示文稿创建／编辑／渲染／技术校验能力 | [Office](office-delivery.md) |
| PDF 阅读、填写、生成、转换、版面核验 | 当前平台原生 PDF 读取／渲染／填写／生成／转换／技术校验能力 | [Office](office-delivery.md) |
| 单点公开事实、版本核实 | 当前可用的轻量公开事实核验能力；OpenAI 产品用当前官方文档能力 | [研究与事实](research-facts.md) |
| 多来源专题、政策／行业研究、复杂证据综合 | `sol-research` | [研究与事实](research-facts.md) |
| KPI、数据质量、诊断、报告 | 相应 `data-analytics:*` 专项能力 | [台账与数据](ledger-data.md) |
| 陌生仓库只读体检 | `repo-health-check` | [仓库与安全](repository-security.md) |
| 鉴权、密钥、注入、供应链 | `security-audit` | [仓库与安全](repository-security.md) |
| Codex/OpenAI 设置、Skill、模型、API | 当前官方 OpenAI 文档能力；失败诊断按专项能力 | [Codex Adapter](../platform-adapter/codex.md) |
| 产图或改图 | 仅用户明确要求时使用当前图像生成／编辑能力 | 当前图像要求 |
| 浏览已登录网页或本地 Web UI | 仅任务需要交互状态时用 Browser/Chrome 控制 | 保密和授权边界 |

## 路由规则

- **禁止同类双技能叠加**：Cabinet 激活后，不得出现“官方文件 Skill 先完整跑一遍，Cabinet 再完整跑一遍”，也不得反向串行；任务理解、计划、编排与最终门禁始终只有 Cabinet 一套。
- 宿主若自动分派或强制加载某个官方文件 Skill／说明，只提取并遵守其中不可覆盖的技术、安全和格式约束，把实际文件操作作为 Cabinet 计划中的原子步骤执行；不得另起第二份计划、第二轮重排或第二套总审。
- 同一转换或生成阶段默认只用一个底层执行器。只有首选能力不可用、明确失败或缺少必要功能时才切换备用能力；备用是替代，不是叠加。
- 平台已完成的文件读取、OCR／文本提取、PDF 渲染、Word／Excel／PPT 创建、格式处理和技术校验直接复用结果。没有失败、证据冲突或必要独立复核时，不重复执行同类 OCR、渲染、排版、解析或全文技术检查。
- 当前环境没有所需能力时，不得伪称已调用；使用当前允许的等价能力或报告降级。
- 专门能力用于完成当前授权目标；不能覆盖用户的工具禁令、保密要求、微改边界或阶段停止条件。
- 涉密材料禁止发送给网页、连接器或外部研究工具；公开政策可用去敏关键词单独查询。
- 审阅请求默认只读。只有用户明确要求修改，或原请求本身已经授权修改，才进入写入链。
- 一个任务可以命中多个领域，但只加载会改变决策或交付方式的 Cabinet 模块；底层文件能力不因此升级为第二个领域中枢。

## 公共组件

文件结构、保真线索和旧值候选按需使用 [公共能力](common-components.md)，不建立 Office、Writer、PDF 或 Spreadsheet 第二中枢。公共读取不得绕过原稿门禁；平台原生文档、表格、演示和 PDF 能力继续负责各自必要的底层生成与技术校验，Cabinet 不复制其通用实现。
