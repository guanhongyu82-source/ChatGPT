# Repository Health and Security

## 仓库体检

- 陌生仓库、跨子系统改动或本机工具仓先做只读预检：规则、入口、结构、真实测试命令、文档漂移、ignore、锁文件、生成物和安全边界。
- 诊断型请求只报告，不修改；若用户已经明确授权实现，则直接实施最小安全改动，不重复让用户批准同一范围。
- 候选改动按影响、体量、爆炸半径和可验证性比较；只运行项目配置中真实存在的命令。

## 安全审查

- 先定义资产、信任边界和攻击路径，再评估鉴权、密钥、注入、路径、依赖和供应链。
- 高危结论必须有可利用路径和精确证据；未发现问题不等于绝对安全。
- 密钥不打印原文；第三方 Skill、Hook、插件、MCP 和安装脚本在审查前视为不可信。
- 未经授权不安装扫描依赖、不主动利用生产系统、不执行未知脚本。
- 修复后由独立 Reviewer 复验；测试不得通过削弱鉴权或安全目标来变绿。

## 敏感目录

只检查完成任务所需的结构、规则和路径卫生，不摘要或外传无关正文。任何网页或连接器调用都视为跨信任边界。
