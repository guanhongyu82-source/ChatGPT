# Office Delivery

## 原稿门禁

- 既有输入在正文读取、解析、接受修订、转换、清理元数据或修改前，先复制至本任务 `00_原稿/` 并核验。清单包含角色、原始文件名、相对路径、大小、源与副本 SHA-256、逐字节一致和原件保护状态；源路径按保密要求最小披露。
- 任意 T 级均不得覆盖原稿。转换、接受修订或元数据清理后的文件不是原稿；默认新建带版本的成果，不覆盖历史正式版。归档失败为 BLOCKED，停止相关正文处理。
- 无源文件不建空目录；中间件置于任务内受控 scratch，只清理本次登记对象。

## 文件位置与最小留存

- 上级指定的工作目录、`work/` 与 `outputs/` 优先；不得为套用本机规则搬离指定输出目录。其余任务按平台适配的任务根及已办归档位置执行，一项工作一个任务夹。
- 没有用户指定扁平目录时，文件型任务默认采用最小三分区：`00_原稿/`（仅真实输入原稿）、`work/`（必要过程、审核和机械证据）、`outputs/`（仅最终交付成品）。无对应内容的分区不为形式空建。
- 用户已明确指定最终输出目录时，以该目录为准；过程文件、审核证据、临时解析和测试件仍放受控 `work/` 或 scratch，不得为方便混入最终输出目录。
- **T1-T2 快车道文件任务**：满足“单输入→单输出、目标格式和位置明确、无新增事实、无正文改写、无复杂模板迁移、无批量耦合、无高风险或独立审核要求”时，预期成品直接以用户当前要求为唯一 Expected，在会话内锁定源文件、目标格式／文件、目标位置和必要抽检；宿主未强制 Hook／契约时，不为形式另建 Task Card、Delivery Contract、Review Gate 或审核 JSON。
- **非轻量文件任务或宿主强制门禁**：在 Task Card 的 `deliverables` 锁定预期成品，不另建第二份 Expected 清单。每个预期成品至少包含 `artifact_id`、`required`、`format`、`target_role`、`target_directory`；用户明确指定文件名时写入 `filename_override`，否则为 null。Delivery Contract 只保存 Task Card 的绝对路径和 SHA-256 锁，不复制 `deliverables`；`artifacts` 只记录 Actual。
- 正式契约路径下，交付前逐项做 Expected ↔ Actual 机械对账：必交项缺失 FAIL；出现未授权 `artifact_id` FAIL；格式、角色或目标目录不符 FAIL；Expected 为 `final` 而 Actual 仍是 `candidate` FAIL；用户指定文件名与实际不符 FAIL。快车道则直接核“用户要求的一个成品是否真实存在、格式／位置／名称是否正确”，不为了得到同一结论再落盘一次机械契约。
- 正式文件用 `YYYY-MM-DD_文种_主题_v1.后缀`（主题3—10字，无空格）；用户指定名称优先。正式契约任务的命名例外来自 `filename_override`；快车道直接以用户当前明确命名为准。原稿保留原名，过程文件集中到上级指定 `work/`，未指定时用 `.scratch/<run_id>/`。
- 计划、分级和内部审阅默认留在会话；仅必要交接、复杂任务或宿主门禁要求才落盘。交付保留原稿、最终成果和必要核验证据，清理本次登记的无价值临时项；不为了检查再生成成套过程报告。
- 平台允许且任务已办时整夹归档，再报告真实最终路径；指定输出目录不允许搬迁时记录“延后归档”及原因，不声称已归档。不创建无必要兼容副本或软链。

## 最终目录白名单

最终交付目录执行“成品白名单”原则：

- **允许进入**：快车道中用户明确要求的最终成品，或正式契约中 Task Card `deliverables` 已授权且在 Actual 中完成对账的最终 Word／Excel／PPT／PDF／CSV 等正式成果，以及用户明确要求一并交付的附件。
- **不得进入**：`delivery-contract.json`、Task Card、Review Gate、独立审核 JSON、解析结果、日志、测试件、缓存、临时转换件、备份包、锁文件、候选草稿和脚本输出；这些内容如确需保留应在 `work/` 或维护证据目录。
- 原稿只有在用户明确要求最终交付目录同时包含原稿时才复制进入；否则留在 `00_原稿/`。
- 交付前实际枚举最终目录一次并核对：应有成品是否全部存在、是否出现未登记额外文件、文件名和版本是否正确。目录不干净时定向整理，不另启动第二轮全目录审查。

## 底层能力复用

Cabinet 只定义本任务的业务目标、中文办公规则和验收条件；具体文件读写、转换、渲染、格式处理和技术校验优先直接调用当前平台成熟的原生能力。宿主若要求加载官方文件 Skill／说明，只把其中不可覆盖的技术、安全和格式要求并入 Cabinet 的单一路径，不执行其与 Cabinet 重叠的独立规划、重排、复核或总结流程。

- 同一生成、转换、渲染或校验阶段默认只使用一个底层执行器；首选能力成功后不再用第二套同类工具“再做一遍”。
- 平台已提供稳定的文件读取、OCR／文本提取、PDF 渲染、Word／Excel／PPT 创建、格式处理和技术校验时，Cabinet 不重新实现同类通用能力，也不重复指导其内部步骤。
- 只有原生能力不可用、明确失败、输出证据冲突或缺少任务必需功能时才启用替代路径；替代路径取代失败环节，不与原路径叠加。
- 永久禁止 LibreOffice、LibreOfficeDev、`soffice` 及相关转换、渲染链。需要视觉确认时优先复用平台当前原生渲染／预览结果；没有必要不得再启动第二套渲染链。

## PDF 转 Word 与简单转换快车道

PDF→Word、Word／PDF 简单格式转换、单文件排版还原、格式对齐等任务，满足快车道条件时按以下单路由完成：**内部快速定级 → 原稿保护 → 一次原生执行 → 一次联合抽检 → 交付**。不得插入无收益的长规划、重复读取、第二轮全文排版或第二套技术总审。

1. **快速识别后直接执行**：T0 只确认源文件、目标格式／位置、是否允许正文改写、是否存在高风险或复杂模板要求；条件明确即进入执行，不等单独的规划消息或完整任务卡。
2. **原文忠实**：转换默认不得擅改文字、数字、日期、主体、标点、表格内容、附件关系或语义；格式优化不能变成内容润色。只有用户明确授权编辑时才修改正文。
3. **读取与 OCR 一次化**：已有可用文本层或平台已成功提取文本时直接复用，不重复 OCR。仅扫描件、文本层不可用或提取明显失败时使用一次必要 OCR；低置信区定向核对，不把整份文档再次 OCR 当保险。
4. **空白扫描页删除、有效分页保留**：纯空白扫描页／背面空白页（无有意义文字、印章、手写、表格、图片或附件分隔信息）应删除；不为复刻扫描纸张制造无内容 Word 空白页。正文换页、章节边界、附件起页、表格或图片布局等有效分页尽量保持；需要保留逻辑分页时使用分页／分节，不以物理空白页代替。
5. **公文与版式忠实**：优先还原源文件可观察到的标题层级、段落层级、缩进与间距、页眉页脚、页码位置与连续性、附件名称及另页关系、表格／图片位置、字体与字号等版式信息。用户或模板已明确公文规范时按其执行；源文件无法可靠判断某项字体或规范且用户未指定时，不凭猜测虚构精确字体，只保持可验证的层级与版式一致性。
6. **一次成型优先**：平台原生布局能力达到目标后不再另起第二轮全文排版。发现局部错页、表格错位、标题层级、附件分页、页码、页眉页脚或字体异常，只修受影响处；若抽检显示系统性转换失败，切换一次合适的替代路径或报告限制，不连续叠加多套工具逐页试错。
7. **一次联合抽检**：最终只安排一轮必要抽检，把内容忠实、版式和技术可用性合并检查。抽检至少覆盖首尾、标题／正文层级代表页、附件起页、分页／空白页节点、页码变化点以及存在表格或图片的高风险页；平台已有可复用技术校验结果直接纳入本轮，不再重跑同类检查。
8. **只在有证据时扩大复核**：抽检未发现系统性问题即交付；只有抽检发现系统性错误、任务本身高风险或用户明确要求逐页核验时，才扩大检查范围。返工后只复验改动处和受影响分页，不重新全文复核未变化部分。

## 成品文稿的交付门槛

- 用户明确要求 Word、Excel、PPT、PDF 或其他实体文件时，必须实际生成并交付对应文件；聊天中的完整正文、说明或代码不能替代用户要求的成品。
- 对未指定文件格式的完整正式文稿，宿主支持文件生成时优先生成标准 `.docx`；在纯 Chat 写作场景且用户只要求文本起草时，可直接在对话可编辑文本中交付，不为满足形式强制制造文件。
- 已有 Word 原稿时生成新版本，不覆盖原稿；无原稿时在当前任务目标目录创建命名清晰的 `.docx`。
- 分析答疑、审阅意见、修改建议、短摘要、提纲、清单、代码、数据结果或用户尚未要求形成完整稿件的内容，不因字数自动升级为 Word 交付。

## 保真与局部修改

先确认本次编辑物件和范围。只改一句、一段或已知字段时走短路径，不因后缀自动启动多岗。保留原位结构、格式、字段、修订、表格及说明；新增段落、作者、颜色、字体按当前明确要求或模板，不把历史个案写成通用默认。

多源、模板保真与方法迁移复用 [材料包](formal-writing.md)，记录表格／工作表、页眉页脚、文本框、公式、扫描页等实际覆盖及未核项；局部任务仅检查修改及受影响部分，不强制每份文件全套画像。

不因普通 PAGE 页码域设置全局 `w:updateFields=true`。确需自动刷新目录、引用或链接域时，先核字段与外部关系及授权。

## 成果检查

验证实际路径、命名、内容验收、归档清单与哈希、原件未覆盖、压缩包结构和可打开性。平台已经完成且结果可复用的结构检查、渲染或技术校验不重复执行；Cabinet 只补当前任务尚未覆盖的用户验收项。模板中的表格、说明和关键层级不得静默删除；正式正文不混入内部对账与交付日志。

文件型任务在 PASS 前只做与路径匹配的最小核对：

1. **成品对账**：快车道直接把用户当前要求作为 Expected，与实际唯一成品核格式、名称和位置；正式契约任务才读取锁定 Task Card 的 `deliverables` 与 Delivery Contract `artifacts` 按 `artifact_id` 对账。
2. **目录对账**：枚举最终目录一次；该进的已进，不该进的已移出或有用户明确要求。
3. **交付小结对账**：拟发送给用户的完工小结包含真实成品路径、目录状态、核验结果和未完成项；不得只说“已完成”。

多次读取或批量巡检需要统一定位时，按需使用 [公共只读检查](common-components.md)；已有解析或平台原生校验足够则复用，不重复跑检查器。
