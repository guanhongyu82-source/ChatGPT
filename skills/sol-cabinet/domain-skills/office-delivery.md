# Office Delivery

## 原稿门禁

- 既有输入在正文读取、解析、接受修订、转换、清理元数据或修改前，先复制至本任务 `00_原稿/` 并核验。清单包含角色、原始文件名、相对路径、大小、源与副本 SHA-256、逐字节一致和原件保护状态；源路径按保密要求最小披露。
- 任意 T 级均不得覆盖原稿。转换、接受修订或元数据清理后的文件不是原稿；默认新建带版本的成果，不覆盖历史正式版。归档失败为 BLOCKED，停止相关正文处理。
- 无源文件不建空目录；中间件置于任务内受控 scratch，只清理本次登记对象。

## 文件位置与最小留存

- 上级指定的工作目录、`work/` 与 `outputs/` 优先；不得为套用本机规则搬离指定输出目录。其余任务按平台适配的任务根及已办归档位置执行，一项工作一个任务夹。
- 没有用户指定扁平目录时，文件型任务默认采用最小三分区：`00_原稿/`（仅真实输入原稿）、`work/`（必要过程、审核和机械证据）、`outputs/`（仅最终交付成品）。无对应内容的分区不为形式空建。
- 用户已明确指定最终输出目录时，以该目录为准；过程文件、审核证据、临时解析和测试件仍放受控 `work/` 或 scratch，不得为方便混入最终输出目录。
- 开工时只在 **Task Card 的 `deliverables`** 锁定预期成品，不另建第二份 Expected 清单。每个预期成品至少包含 `artifact_id`、`required`、`format`、`target_role`、`target_directory`；用户明确指定文件名时写入 `filename_override`，否则为 null。`artifact_id` 在本任务内唯一且在后续 Actual 对账中保持不变。
- Delivery Contract 只保存 Task Card 的绝对路径和 SHA-256 锁，不复制 `deliverables`。`artifacts` 仅表示实际成品（Actual），每项至少包含与 Expected 对应的 `artifact_id`、实际 `role`、绝对 `path` 和当前文件 `sha256`。因此用户改变交付数量、格式、角色、目录或指定文件名时，必须先更新 Task Card，并重新锁定／登记契约；只改 Actual 或口头说明不能改变 Expected。
- 交付前逐项做 Expected ↔ Actual 机械对账：必交项缺失 FAIL；出现未授权 `artifact_id` FAIL；格式、角色或目标目录不符 FAIL；Expected 为 `final` 而 Actual 仍是 `candidate` FAIL；用户指定文件名与实际不符 FAIL。可选项允许不交。文件型任务至少有一个 Expected；无文件的分析答疑走 analysis-only，不虚造 Expected 或文件契约。
- 正式文件用 `YYYY-MM-DD_文种_主题_v1.后缀`（主题3—10字，无空格）；用户指定名称优先，且该例外必须来自 Task Card 的 `filename_override`，不能由 Actual 自行声明豁免。原稿保留原名，过程文件集中到上级指定 `work/`，未指定时用 `.scratch/<run_id>/`。
- 计划、分级和内部审阅默认留在会话；仅必要交接或宿主门禁要求才落盘。交付保留原稿、最终成果和必要核验证据，清理本次登记的无价值临时项；不为了检查再生成成套过程报告。
- 平台允许且任务已办时整夹归档，再报告真实最终路径；指定输出目录不允许搬迁时记录“延后归档”及原因，不声称已归档。不创建无必要兼容副本或软链。

## 月度归档兜底

- 日常仍以“任务办结后即时整夹归档”为主；月度整理只用于收口遗漏，不得把本来已经可以归档的任务故意拖到月底。
- 每个自然月结束或进入下一自然月后的首次实际整理时，检查当前 workspace 中尚未归档的稳定任务夹。已完成、交付对账通过且不存在待反馈、待审批、待返工或继续编辑事项的任务，按**办结月份**归入既有已办归档位置下的 `YYYY-MM/`；不按任务创建月份强行归档。
- 未完成、PARTIAL、BLOCKED、待用户确认、待审批、待反馈或仍需返工的任务即使跨月也继续保留在当前 workspace，不得为了月度整齐强制迁移；满足办结条件后再按实际办结月份归档。
- 月度归档移动的是**完整稳定任务夹**，保持其中 `00_原稿/`、`work/`、`outputs/` 及必要证据的内部关系，不拆散原稿、过程和成品，不把 `outputs/` 单独搬走，也不为归档创建兼容副本或无必要软链。
- 月度整理同时检查 workspace 根部的无业务身份会话目录、孤立上传目录和已登记无价值临时项；只有能够确认不属于进行中任务、正式成品、原稿或必要证据时才清理。无法确认归属、用途或是否仍需使用的内容不得删除，应保留并报告待人工裁决。
- 用户明确指定固定输出目录且不允许移动时，保持该成果原位，并在任务状态中记录“延后归档”及原因；不得为了满足 `YYYY-MM/` 形式复制第二套正式成果。
- 月度整理完成后只需报告实际归档的任务、继续留在 workspace 的未结任务、无法确认的遗留项和真实归档位置；不为月度归档另造整套台账、审核链或后台定时任务。

## 最终目录白名单

最终交付目录执行“成品白名单”原则：

- **允许进入**：Task Card `deliverables` 已授权且在 Actual 中完成对账的最终 Word／Excel／PPT／PDF／CSV 等正式成果，以及用户明确要求一并交付的附件。
- **不得进入**：`delivery-contract.json`、Task Card、Review Gate、独立审核 JSON、解析结果、日志、测试件、缓存、临时转换件、备份包、锁文件、候选草稿和脚本输出；这些内容如确需保留应在 `work/` 或维护证据目录。
- 原稿只有在用户明确要求最终交付目录同时包含原稿时才复制进入；否则留在 `00_原稿/`。
- 交付前必须实际枚举最终目录并核对：应有成品是否全部存在、是否出现未登记额外文件、文件名和版本是否正确。目录不干净时先定向整理，再交付。

## 最小工具路径

文稿、表格、演示默认 `.docx`、`.xlsx`、`.pptx`。使用当前对应 Office／PDF Skill 的必要能力，但用户工具禁令和本阶段范围优先于其通用流程。

永久禁止 LibreOffice、LibreOfficeDev、`soffice` 及相关转换、渲染链。Word 优先一次必要的 macOS Quick Look／系统预览；不得为了核验弹出 Office 应用。无法逐页检查时明确“未完成视觉渲染核验”，继续安全的内容、结构、压缩包与可打开性检查，不启用禁用回退。

## 成品文稿的交付门槛

- 用户明确要求 Word、Excel、PPT、PDF 或其他实体文件时，必须实际生成并交付对应文件；聊天中的完整正文、说明或代码不能替代用户要求的成品。
- 对未指定文件格式的完整正式文稿，宿主支持文件生成时优先生成标准 `.docx`；在纯 Chat 写作场景且用户只要求文本起草时，可直接在对话可编辑文本中交付，不为满足形式强制制造文件。
- 已有 Word 原稿时生成新版本，不覆盖原稿；无原稿时在当前任务目标目录创建命名清晰的 `.docx`。
- 分析答疑、审阅意见、修改建议、短摘要、提纲、清单、代码、数据结果或用户尚未要求形成完整稿件的内容，不因字数自动升级为 Word 交付。

## 保真与局部修改

先确认本次编辑物件和范围。只改一句、一段或已知字段时走短路径，不因后缀自动启动多岗。保留原位结构、格式、字段、修订、表格及说明；新增段落、作者、颜色、字体按当前明确要求或模板，不把历史个案写成通用默认。

多源、模板保真与方法迁移复用 [材料包](formal-writing.md)，记录表格／工作表、页眉页脚、文本框、公式、扫描页等实际覆盖及未核项；局部任务仅检查修改及受影响部分，不强制每份文件全套画像。

不因普通 PAGE 页码域设置全局 `w:updateFields=true`。确需自动刷新目录、引用或链接域时，先核字段与外部关系及授权。

## 成果检查

验证实际路径、命名、内容验收、归档清单与哈希、原件未覆盖、压缩包结构和可打开性。结构检查、系统预览、逐页视觉核验分别报告，不能互相替代。模板中的表格、说明和关键层级不得静默删除；正式正文不混入内部对账与交付日志。

文件型任务在 PASS 前额外执行三项核对：

1. **成品对账**：读取锁定 Task Card 的 `deliverables` 作为 Expected，再与 Delivery Contract 的 Actual `artifacts` 按 `artifact_id` 一一对应；缺项、多项、错格式、错角色、错目录、错指定文件名或 Task Card 哈希过期均未完成。
2. **目录对账**：最终目录只保留白名单成品；该进的已进，不该进的已移出或有用户明确要求。
3. **交付小结对账**：拟发送给用户的完工小结包含真实成品路径、目录状态、核验结果和未完成项；不得只说“已完成”。

多次读取或批量巡检需要统一定位时，按需使用 [公共只读检查](common-components.md)；已有解析足够则复用，不重复跑检查器。
