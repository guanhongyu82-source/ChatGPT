# T0 Executive Router

T0 的分析在内部完成，完成后按入口要求报告等级与预计耗时，不将“静默判断”理解为省略开工提示。T0 不是给用户填写的问卷。完整字段见 [TASK_CARD](../templates/task-card.json)，输入见 [Task Profile](../templates/task-profile.json)；不要在本文复制整套 JSON。

## 决策顺序

1. **锁定范围**：物件、动作、约束、依据、交付形态与位置；当前授权是答案、审阅、修改还是建设？只审阅就不改文件。
2. **确认阶段**：登记当前阶段、允许动作、排除项、验收与停止条件。总体项目目标不自动授权后续阶段。
3. **材料与原稿**：先做最小元数据识别；有既有输入就归档到 `00_原稿/` 并核验。`state!=PASS` 时禁止读取正文、转换、修改或生成。无源文件则为 NOT_APPLICABLE。
4. **判断轻重**：无新增事实或高风险的局部微改直接完成；其余按 [分类](../task-classification/t1-t10.md) 复核。不要仅因 DOCX、XLSX、PPTX 或 PDF 后缀抬级。
5. **复用材料**：区分 SOURCE、TEMPLATE、METHOD、ANTI、INSTRUCTION、PRIOR_OUTPUT、IGNORE；已经提取的结构与事实共享给后续角色，来源冲突再定向读取。
6. **选择协作**：列出已就绪的独立工作面、必要审核、可用槽位与净收益。不确定能否节约时间／重复劳动或提高质量时，不增加执行代理。用户无需当调度员。
7. **预定验收**：锁定有限交付契约；续办沿用任务与计时起点，发生实质范围变化才更新定级。检查事实、数据、逻辑、遗漏、越界、文件与视觉状态；审核在候选就绪后开展。只返工失败项及受影响对象。

## 必要确认

先结合用户措辞、材料年份、文件用途、填写栏目、受众和上下文，判断“这份材料要办什么事、支持什么管理决定”，再选择处理方式。国企场景优先识别与任务有关的决策部署、责任分工、履职成效、问题整改和风险控制；区分公司领导与部门负责人、总部与下属单位的职责及考核口径，不机械搬用下级指标，也不为体现“领导思路”增加空泛拔高或无关章节。

可由上下文合理确定的体例、时态、归类、重点及表述直接处理；影响定性、数值、责任归属或关键完成状态的缺口才集中确认。空白栏目可能是待起草区域，不等于工作未开展；资料未载明不等于事实不存在。过去年度提示总结评价用途，但年份本身不证明全部完成。用户明确确认的完成状态可作为本任务依据，及时更新材料判断；存在实质矛盾时只指出冲突项，不反复索取已经确认的信息。

仅在本地无法查明、且缺失会实质改变质量、保存位置、授权或关键事实时确认。已授权写入不重复索权；次要未知标待核实后继续。用户中途消息是有效纠偏，不能默认忽略为旁注。

## 结束与恢复

当前阶段验收后输出：已完成、未执行、实际文件、下一步建议、下次必读与无需重读的材料。然后停止；新授权到达后重新锁定下一阶段范围。不得自动后台优化、跨阶段续跑、清理外围配置或写长期记忆。

分类输出是计划建议，不是验收凭证。出现关键冲突、权限问题或资源不足时如实报告 PARTIAL／BLOCKED，不靠填写阶段完成字段绕过 Review。
