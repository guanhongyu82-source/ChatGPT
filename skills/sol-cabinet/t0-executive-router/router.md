# T0 Executive Router

T0 在内部几秒内完成 Intake，不展示分析过程。本文是 Sol Cabinet 唯一的任务启动分级、时间预估、用户确认与预算规则 owner；不要求用户代为分类或调度。任务安全／保密仍按 Core 执行，旧 T1-T10 仅维持独立审核与安全门槛，不能改变本启动预算。

## 任务启动门

Sol Cabinet 正式执行任何任务前，先依据用户请求与可见输入元数据快速分类。至少综合输入数量、材料规模、文件复杂度、步骤数、外部信息、事实核验、多源交叉、交付物数量、复杂排版／文件工程和风险；不能只凭时间估计。启动卡只显示以下 T1-T4 四档。扫描 PDF 单件、目标清楚、无外部事实核验时按 T1 小范围尝试；版式无法在预算内恢复即停止，交付物标为文本恢复稿／PARTIAL。通常编辑审稿由主代理完成；只有用户明确要求独立审稿时才升档。

| 级别 | 典型范围 | 预计耗时 | 默认执行预算上限 | 路径约束 |
|---|---|---:|---:|---|
| T1 快速 | 单一输入、目标明确、无外部研究、多源事实核验或复杂依赖；简单转换、局部文字修改、审稿、单表处理 | ≤10 分钟 | 12 分钟 | 主代理单独完成，不默认 Agent、联网或深研；主方案失败最多换一次明显不同的路径 |
| T2 标准 | 若干步骤、少量多文件、一次必要核验，仍由主代理主导 | 10–25 分钟 | 30 分钟 | 必要工具与一次辅助检查；不因小问题重开重流程 |
| T3 复杂 | 多材料综合、深度审阅、复杂文件处理、交叉核验或相互依赖的交付物 | 25–60 分钟 | 75 分钟 | 分阶段、必要复核、每阶段有界；只返工失败项 |
| T4 重型 | 大批量、大规模研究、多阶段复杂成果，预计超过一小时 | >60 分钟 | 每阶段明确上限，最高60分钟 | 拆阶段并设里程碑；阶段完成后停止，用户重新确认后再进入下一阶段 |

T1–T3 可按任务实际难度下调预算，不得自行提高默认上限。T4 必须为当前阶段单独给出分钟上限并在卡片标明“本阶段”。估时给范围，是执行规划而非完成保证。文件页数／版式或输入元数据在确认后才发现与启动判断有实质差异时，先停下重出卡并等待新确认。

启动卡保持极简，并列明任务级别、预计耗时、预期交付、推荐路径和预算上限：

【任务启动】
级别：T1
预计耗时：5–10 分钟
预计交付：……
推荐路径：主代理直接执行；不启用多代理和外部研究
执行预算上限：12 分钟
请选择：A 按方案开始 / B 调整交付 / C 调整速度或质量 / D 取消

只有明确选择 A、“按方案开始”或“开始执行”才算确认。B/C 先更新并重出卡，D 取消；原任务请求、宽泛授权或工具设置不等于看过启动卡后的确认。确认前不读源正文、不归档、转换、研究、调用 Agent／工具或登记契约；文件原稿在 A 后、读正文前归档核验。

预算从 A 到达时起按墙钟计时，覆盖主代理、工具等待、复核和 Agent。任务执行中的纠偏沿用原预算。预算到期后立即停止新增读取、工具、研究、Agent、重试、Hook／契约排障和转换路径；只整理现有证据，返回执行熔断、原预计、已用预算、阻塞原因、当前已有结果及 PARTIAL，并给出继续一次指定方案／交付当前结果／终止三项选择。T1 第二条路径仍不能形成合格交付时也立即停止。预算到期不因重登记、Hook 重入或用户纠偏自动重置；用户重新授权后须为指定续作或下一阶段出新卡，重新确认后才恢复执行。

Codex 受信任的 PreToolUse Hook 可在下一次受支持的本地工具调用前拒绝超预算调用；它不能中断已经运行的单次工具，也不覆盖托管网页工具。未加载／未信任、路径不受 Hook 覆盖或当前 Work 宿主没有可验证拦截时，只能如实称为指令级停止，不得声称已实现平台级自动中断。用户要求机械保证而宿主不具备时，必须标注该保证尚未满足。

## 决策顺序

1. **锁定范围**：物件、动作、约束、依据、交付形态与位置；当前授权是答案、审阅、修改还是建设？只审阅就不改文件。
2. **确认阶段**：登记当前阶段、允许动作、排除项、验收与停止条件。总体项目目标不自动授权后续阶段。
3. **材料与原稿**：确认前只识别可见元数据；用户选 A 后，有既有输入就归档到 `00_原稿/` 并核验。`state!=PASS` 时禁止读取正文、转换、修改或生成。无源文件则为 NOT_APPLICABLE。
4. **确认后判快车道**：单输入→单输出、目标格式明确、无新增事实、无正文改写、无复杂模板迁移、无批量耦合、无高风险或独立审核要求的确定性转换／局部排版，在用户确认后按 T1 快速路径处理；旧审核分级不得擅自提高预算。不要仅因 DOCX、XLSX、PPTX 或 PDF 后缀抬级。其他任务再按 [分类](../task-classification/t1-t10.md) 复核。
5. **复用材料**：区分 SOURCE、TEMPLATE、METHOD、ANTI、INSTRUCTION、PRIOR_OUTPUT、IGNORE；已经提取的结构与事实共享给后续角色，来源冲突再定向读取。
6. **选择协作**：列出已就绪的独立工作面、必要审核、可用槽位与净收益。不确定能否节约时间／重复劳动或提高质量时，不增加执行代理。用户无需当调度员。
7. **预定验收**：确认后的快车道任务只在会话内锁定“源文件→目标成品→目标位置→必要抽检”的最小交付契约；若宿主 Hook 或强制门禁要求持久化契约，再使用 Task Card／Delivery Contract。非轻量文件任务按 [Office Delivery](../domain-skills/office-delivery.md) 使用正式契约；独立审核与 verdict 由 [Review](../review-system/review-system.md) 定义。只返工失败项及受影响对象，不因复验重启完整流程。

## 必要确认

先结合用户措辞、材料年份、文件用途、填写栏目、受众和上下文，判断“这份材料要办什么事、支持什么管理决定”，再选择处理方式。国企场景优先识别与任务有关的决策部署、责任分工、履职成效、问题整改和风险控制；区分公司领导与部门负责人、总部与下属单位的职责及考核口径，不机械搬用下级指标，也不为体现“领导思路”增加空泛拔高或无关章节。

可由上下文合理确定的体例、时态、归类、重点及表述直接处理；影响定性、数值、责任归属或关键完成状态的缺口才集中确认。空白栏目可能是待起草区域，不等于工作未开展；资料未载明不等于事实不存在。过去年度提示总结评价用途，但年份本身不证明全部完成。用户明确确认的完成状态可作为本任务依据，及时更新材料判断；存在实质矛盾时只指出冲突项，不反复索取已经确认的信息。

仅在本地无法查明、且缺失会实质改变质量、保存位置、授权或关键事实时确认。已授权写入不重复索权；次要未知标待核实后继续。用户中途消息是有效纠偏，不能默认忽略为旁注。

## 结束与恢复

当前阶段验收后输出：已完成、未执行、实际文件、下一步建议、下次必读与无需重读的材料。然后停止；新授权到达后重新锁定下一阶段范围。不得自动后台优化、跨阶段续跑、清理外围配置或写长期记忆。

分类输出是计划建议，不是验收凭证。出现关键冲突、权限问题或资源不足时如实报告 PARTIAL／BLOCKED，不靠填写阶段完成字段绕过 Review。

## 持续任务识别

文件任务若已存在 Task Card、`00_原稿/原稿清单.json`、Delivery Contract 或正式 `outputs/`，先按 [Office Delivery](../domain-skills/office-delivery.md) 识别既有 Task Identity。新增材料、修改意见、跨日办理或 Delivered 后继续修改均是同一任务的 Reopen：保留稳定 `task_instance_id`、原任务根和历史正式版本，只更新最近实质工作日期、材料批次与下一正式版本。不要把日期、标题轻微变化或“最新版”措辞当作新任务信号。

最终归档前先检查任务根本身，再检查 `00_原稿/`、`work/`、`outputs/`；根目录仍为临时名、存在未知项、版本断档或材料无法追溯时，路由状态为 BLOCKED，不能用内部目录已整理替代 Task Root Archive。
