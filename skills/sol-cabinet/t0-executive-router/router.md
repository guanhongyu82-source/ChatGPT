# T0 Executive Router

T0 对每个已激活的新 Cabinet 任务执行理解、T1-T10 判级和实际路由。正式工作前必须展示一张轻量开工卡；T1-T2 不例外，但无需落盘 Task Card。卡片包含目标、T级、范围／排除项、交付、验收、停止条件、`started_at`（待确认）和确认方式。明确直接执行的请求仍先出卡，标“用户已预授权”，然后即可开始；否则停在 `START_CARD_READY` 等自然语言确认。确认或预授权后再写入实际 `started_at`，未确认不得正式写文件。

T0 不另定义开工字段或耗时规则；卡片字段见 [Skill 入口](../SKILL.md)，时间由 Codex 生命周期 Hook 记录。T0 不是用户填写的问卷。完整文件交付字段仍见 [TASK_CARD](../templates/task-card.json)，输入见 [Task Profile](../templates/task-profile.json)。轻任务只在会话内保留开工卡，不复制完整 JSON。任务分类与执行深度由 [T1-T10](../task-classification/t1-t10.md) 唯一规定；时间由 Codex 生命周期 Hook 记录，不承诺未来时长。

## 决策顺序

1. **锁定范围与授权**：识别物件、动作、约束、依据、交付形态与位置；区分答复、审阅、修改和建设。只审阅就不改文件；项目后续阶段须单独授权。
2. **按 T1-T10 判级并选执行深度**：基于范围、工作量、风险、不确定性、证据、交付形式和持续性判级；采用分类输出的 `workflow.lane`。格式本身不升档，风险硬门槛不降级。
3. **展示开工卡并确认**：基于用户要求及必要只读元数据显示卡片。自然语言可确认；用户明确要求直接执行即为预授权，但仍先显示卡片。改范围则旧卡失效并重判，取消则停止。
4. **材料与原稿**：确认后、读取正文前，将既有输入逐字节归档到 `00_原稿/` 并核验；`state!=PASS` 时禁止读正文、转换或修改。无源文件为 NOT_APPLICABLE。
5. **复用材料与协作**：区分 SOURCE、TEMPLATE、METHOD、ANTI、INSTRUCTION、PRIOR_OUTPUT、IGNORE；已经提取的结构与事实共享给后续角色，冲突再定向读取。仅在有独立工作面和明确净收益时协作。
6. **预定验收**：T1-T2 在会话内锁定源→成品→位置→一次必要抽检，不另建契约文件；非轻量文件任务复用 Office Delivery 的 Task Card／Delivery Contract。只返工失败项及受影响对象。
7. **交付、Evolution、停止**：最终交付门 PASS 后才执行一次 Evolution Checkpoint；有异常时按 failure type 与 cause 读取相关现有 INC/EV/RES/EVO 事实，确认旧机制是否已存在、是否未进入运行路径。状态真实后生成完工小结并停止，不启动后台续作。

## 必要确认

先结合用户措辞、材料年份、文件用途、填写栏目、受众和上下文，判断“这份材料要办什么事、支持什么管理决定”，再选择处理方式。国企场景优先识别与任务有关的决策部署、责任分工、履职成效、问题整改和风险控制；区分公司领导与部门负责人、总部与下属单位的职责及考核口径，不机械搬用下级指标，也不为体现“领导思路”增加空泛拔高或无关章节。

可由上下文合理确定的体例、时态、归类、重点及表述直接处理；影响定性、数值、责任归属或关键完成状态的缺口才集中确认。空白栏目可能是待起草区域，不等于工作未开展；资料未载明不等于事实不存在。过去年度提示总结评价用途，但年份本身不证明全部完成。用户明确确认的完成状态可作为本任务依据，及时更新材料判断；存在实质矛盾时只指出冲突项，不反复索取已经确认的信息。

仅在本地无法查明、且缺失会实质改变质量、保存位置、授权或关键事实时确认。已授权写入不重复索权；次要未知标待核实后继续。用户中途消息是有效纠偏，不能默认忽略为旁注。

## 结束与恢复

当前阶段验收后输出：已完成、未执行、实际文件、下一步建议、下次必读与无需重读的材料。然后停止；新授权到达后重新锁定下一阶段范围。不得自动后台优化、跨阶段续跑、清理外围配置或写长期记忆。

分类输出是计划建议，不是验收凭证。出现关键冲突、权限问题或资源不足时如实报告 PARTIAL／BLOCKED，不靠填写阶段完成字段绕过 Review。

## 持续任务识别

文件任务若已存在 Task Card、`00_原稿/原稿清单.json`、Delivery Contract 或正式 `outputs/`，先按 [Office Delivery](../domain-skills/office-delivery.md) 识别既有 Task Identity。新增材料、修改意见、跨日办理或 Delivered 后继续修改均是同一任务的 Reopen：保留稳定 `task_instance_id`、原任务根和历史正式版本，只更新最近实质工作日期、材料批次与下一正式版本。不要把日期、标题轻微变化或“最新版”措辞当作新任务信号。

最终归档前先检查任务根本身，再检查 `00_原稿/`、`work/`、`outputs/`；根目录仍为临时名、存在未知项、版本断档或材料无法追溯时，路由状态为 BLOCKED，不能用内部目录已整理替代 Task Root Archive。
