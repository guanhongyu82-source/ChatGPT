# Sol Cabinet Changelog

本文件记录 Sol Cabinet 的正式版本变化。当前版本号的唯一权威仍为 [`VERSION`](VERSION)；本文件只记录发布事实、变更范围与验证边界，不成为 Core、Office、Review、Router 或其他规则域的第二政策来源。

## v1.5.4 — 2026-09-17 — FINAL

### 定稿结论

v1.5.4 将此前暴露于简单文件任务中的重复控制链正式收敛为单一路径：**Sol Cabinet 是唯一上层任务理解、流程规划、执行编排和质量门禁；平台官方 PDF／DOCX／XLSX／PPTX 及文件读取、OCR／提取、渲染、创建、格式处理和技术校验能力只作为底层原子执行能力，禁止同类双技能叠加。**

本版属于向后兼容的控制面减重与边界澄清，不改变 Sol Cabinet 的任务使命、主结构和 T1—T10 分级。

### 本版纳入的小颗粒变更

1. **唯一上层编排**
   - 在 Core 固化 Cabinet 唯一总控身份。
   - 禁止“官方 Skill 完整跑一遍、Cabinet 再跑一遍”以及反向串行。
   - 宿主强制的官方技术／安全要求并入 Cabinet 同一路径，不形成第二规划或第二总审。

2. **官方能力降为原子执行层**
   - 文档、表格、演示、PDF 的读取、转换、渲染、创建、格式处理和技术校验优先复用平台成熟能力。
   - Cabinet 不重新实现、不重复指导平台已经成熟的通用内部步骤。
   - 同一生成、转换、渲染或校验阶段默认只保留一个主执行器；备用路径只在首选能力不可用、失败、证据冲突或缺少必要功能时替代失败环节。

3. **Office／PDF 路由收敛**
   - `domain-skills/routing-map.md` 从“多个完整 Skill 路由”收敛为“Cabinet 单路由 + 底层原子能力”。
   - 文件类型本身不再触发第二套上层工作流或全套 Office 能力。

4. **简单转换与排版短路径**
   - PDF→Word、Word／PDF 简单格式转换、单文件排版还原和格式对齐，满足低风险条件时保持轻量路径。
   - 原稿保护后执行一次主要原生转换／创建／排版，成功后直接进入必要验收。
   - 转换任务默认原文不擅改；有意空白页、分节和分页结构保留，转换误生的多余空白页定向清理。
   - 不为像素级一致反复全文重排，只对明显错页、表格错位、标题层级、页眉页脚等受影响处返工。

5. **OCR、渲染与全文复核去重**
   - 已有可用文本层或平台已成功提取文本时不重复 OCR。
   - OCR 仅在扫描件、文本层不可用或提取明显失败时使用，并只定向核对低置信区。
   - 已有可复用渲染／技术校验结果时不再启动第二套同类检查。
   - 简单任务默认抽检首尾、关键转换页、分页／空白页节点、表格和图片；只有发现系统性问题、高风险或用户明确要求时扩大全文复核。

6. **Review 只补差异化验收**
   - 平台原生技术校验可直接作为技术证据复用。
   - Cabinet Review 聚焦用户专属业务规则、中文办公规范、质量标准、异常点和最终验收。
   - 独立审核不等于必须重复调用同类技术工具；证据缺失、冲突、失败或高风险时才定向重跑。

7. **Hot Path 减重原则落地**
   - 将“官方能力与 Cabinet 各自规划、各自执行、各自检查”的双链路明确视为 Hot Path 缺陷。
   - 优先通过复用、删除重复指导、单路由和结果复用降低普通任务控制面，不通过新增 Agent、Domain、Gate 或第二工作流解决。

### 本版明确未改变

- 主目录结构与既有 canonical owner 架构未重构；
- T1—T10 分级规则未改变；
- 原稿保护与不覆盖源文件原则未改变；
- Expected ↔ Actual、最终目录白名单和真实成品验收未取消；
- 保密、阶段授权、停止条件和用户工具禁令未弱化；
- 不新增 Domain、Agent、常驻 Gate、第二工作流或新的平台替代实现；
- 不扩大 ChatGPT Cabinet 的任务边界，也不恢复其他 AI 系统的活动连接。
