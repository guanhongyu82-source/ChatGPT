# Sol Cabinet Changelog

本文件记录 Sol Cabinet 的正式版本变化。当前版本号的唯一权威仍为 [`VERSION`](VERSION)；本文件只记录发布事实、变更范围与验证边界，不成为 Core、Office、Review、Router 或其他规则域的第二政策来源。

## v1.5.4 — 2026-09-17 — FINAL

### 定稿结论

v1.5.4 将简单文件任务中的重复控制链正式收敛为单一路径：**Sol Cabinet 是唯一上层任务理解、流程规划、执行编排和质量门禁；平台官方 PDF／DOCX／XLSX／PPTX 及文件读取、OCR／提取、渲染、创建、格式处理和技术校验能力只作为底层原子执行能力，禁止同类双技能叠加。**

本版属于向后兼容的控制面减重、边界澄清和快车道优化，不改变 Sol Cabinet 的任务使命、主结构和 T1—T10 分级体系。

### 第一阶段：官方能力与 Cabinet 边界收敛

1. **唯一上层编排**
   - 在 Core 固化 Cabinet 唯一总控身份。
   - 禁止“官方 Skill 完整跑一遍、Cabinet 再跑一遍”以及反向串行。
   - 宿主强制的官方技术／安全要求并入 Cabinet 同一路径，不形成第二规划或第二总审。

2. **官方能力降为原子执行层**
   - 文档、表格、演示、PDF 的读取、转换、渲染、创建、格式处理和技术校验优先复用平台成熟能力。
   - Cabinet 不重新实现、不重复指导平台已经成熟的通用内部步骤。
   - 同一生成、转换、渲染或校验阶段默认只保留一个主执行器；备用路径只在首选能力不可用、失败、证据冲突或缺少必要功能时替代失败环节。

3. **Office／PDF 路由收敛**
   - `domain-skills/routing-map.md` 从“多个完整 Skill 路由”收敛为“Cabinet 单路由 + 底层原子能力”。
   - 文件类型本身不再触发第二套上层工作流或全套 Office 能力。

4. **OCR、渲染与全文复核去重**
   - 已有可用文本层或平台已成功提取文本时不重复 OCR。
   - 已有可复用渲染／技术校验结果时不再启动第二套同类检查。
   - Review 聚焦用户专属业务规则、中文办公规范、质量标准、异常点和最终验收。

### 第二阶段：质量不降、速度提升最终收口

2026-09-17 用户明确要求在保持 v1.5.4 版本号的前提下完成最终“质量不降、速度提升”专项优化。该轮以 PR #6 `cabinet: finalize v1.5.4 speed-quality fast path` 为审核载体，重点削减只有时间成本、没有可验证质量收益的串行控制步骤。

1. **T1-T2 确定性文件快车道**
   - 将“单输入→单输出、目标格式和位置明确、无新增事实、无正文改写、无复杂模板迁移、无批量耦合、无高风险或独立审核要求”的文件转换／局部排版纳入 T1-T2 快车道。
   - 快车道内部完成 T0 定级后直接执行，不再为展示规划单独发送一轮开工计划。
   - 非轻量、高风险、正式发布、事实核查、复杂模板迁移和显式独立审阅仍按原等级与审核强度执行，不因“要快”降档。

2. **轻量契约内存化**
   - 快车道直接以用户当前要求作为唯一 Expected，在会话内锁定源文件、目标格式／文件、目标位置和必要抽检。
   - 宿主未强制 Hook／持久化契约时，不为形式另建 Task Card、Delivery Contract、Review Gate 或审核 JSON。
   - 非轻量任务和宿主强制门禁仍保留正式契约、Expected ↔ Actual 对账和机械 Gate。

3. **PDF→Word 单路由一次成型**
   - 固化路径：**内部快速定级 → 原稿保护 → 一次原生执行 → 一次联合抽检 → 交付**。
   - 原文不得擅改文字、数字、日期、主体、标点、表格内容、附件关系或语义；格式优化不得变成内容润色。
   - 纯空白扫描页／背面空白页应删除；正文换页、章节边界、附件起页、表格图片布局等有效分页尽量保持。
   - 优先还原源文件可观察到的标题层级、段落层级、缩进与间距、页眉页脚、页码位置与连续性、附件名称及另页关系、表格／图片位置、字体与字号。源文件无法可靠判断且用户未指定的精确字体不凭猜测补造。

4. **一次联合抽检代替多轮全文复核**
   - 把内容忠实、版式和技术可用性合并进一轮必要抽检。
   - 抽检覆盖首尾、标题／正文层级代表页、附件起页、分页／空白页节点、页码变化点和表格／图片高风险页。
   - 平台已有可复用技术校验结果直接纳入，不重复 OCR、渲染、排版或全文技术检查。
   - 只有抽检发现系统性错误、任务本身高风险或用户明确要求逐页核验时才扩大范围。

5. **返工只修受影响项**
   - 局部问题只修受影响处并复验受影响分页／对象，不重新全文复核未变化部分。
   - 系统性转换失败时切换一次合适的替代路径或报告限制，不连续叠加多套工具逐页试错。
   - 快车道不机械进入非轻量任务的三轮修复循环。

6. **质量优先的时延约束**
   - Core 增加硬原则：在达到同一验收标准的路径中选择墙钟时间更短者。
   - 新增串行 Gate、重复读取、重复技术检查、额外 Agent 或过程台账必须有可验证质量收益；不能证明收益时优先删除、合并、并行或降级。
   - 提速不得以削弱原稿保护、事实依据、保密要求或必要验收为代价。

### 质量与速度验收判断

本次稳定版审核以“质量至少不低于当前水平、错误风险下降、返工次数不增加、总耗时应明显缩短”为标准，结论如下：

- **质量门槛未下降**：原稿逐字节保护、原文忠实、真实成品、目录洁净、必要审核、高风险升级、用户明确独立审阅均保留；PDF→Word 的版式验收点反而更明确。
- **错误风险下降方向成立**：明确禁止重复 OCR／重复排版导致的二次漂移，新增空白扫描页识别、有效分页、附件起页、页码、字体／字号和高风险页抽检要求。
- **返工次数不增加**：局部错误采用定向修复与定向复验；系统性失败最多切换一次替代路径，不进入无收益的多工具试错链。
- **关键路径结构明显缩短**：快车道取消独立规划消息、非强制 Task Card／Delivery Contract／Review Gate 落盘以及第二套技术总审，从多段串行控制收敛为“内部定级 → 原稿保护 → 一次执行 → 一次联合抽检 → 交付”。
- **不虚报未测性能**：仓库静态审核可以确认串行控制节点减少，但没有在本次维护中额外构造重复 PDF→Word 实战或秒级性能基准，因此不声称已经测得具体耗时降幅。真实墙钟收益由后续正常办公任务自然验证；若出现可复现质量回归，按既有事故与维护边界定向修复。

基于上述差异审计，本轮达到推送标准：删减项均为无独立质量收益的控制开销，必要质量门槛无缺失，任务边界未扩大。

### 本版明确未改变

- 主目录结构与既有 canonical owner 架构未重构；
- T1—T10 的等级体系、风险升级和独立审核逻辑未改变；仅将确定性低风险单文件转换明确纳入 T1-T2 适用信号；
- 原稿保护与不覆盖源文件原则未改变；
- 非轻量任务的 Expected ↔ Actual、最终目录白名单和真实成品验收未取消；
- 快车道仍必须核真实成品、格式／名称／位置、目录状态和必要抽检；
- 保密、阶段授权、停止条件和用户工具禁令未弱化；
- 不新增 Domain、Agent、常驻 Gate、第二工作流或新的平台替代实现；
- 不扩大 ChatGPT Cabinet 的任务边界，也不恢复其他 AI 系统的活动连接。
