# Sol Cabinet v1.5.5-lab.3

状态：LAB（实验态，不是正式发布）

本版本继承 [v1.5.5-lab.2](v1.5.5-lab.2.md) 的全部实验覆盖，只修复两个已在真实任务中确认的机制缺口，不新增其他能力：

- 1.5.5-023：LAB 已部署且 Runtime 为 `SYNCED`，但执行时仍可能因“实验态/不稳定”而预防性绕回 Stable。
- 1.5.5-024：`/Users/macbook/ChatGPT/workspace/` 下任务目录命名无唯一规则，出现 `YYYY-MM-DD`、`YYYYMMDD`、`YYYYMMDD_主题` 等多种并存格式。

---

## 1. LAB-first 执行选择

### 1.1 当前 LAB 是实际执行版本

当以下条件同时成立时：

- 当前 `VERSION` 含 `-lab.`；
- Runtime deployment state 为 `state=SYNCED`；
- `channel=lab`；
- `source_ref` 与当前 LAB 分支一致；

则**当前 LAB 就是 Sol Cabinet 的默认实际执行版本**。所有正常 Cabinet 任务均从当前 LAB 入口执行，并继承 Stable 基线中未被 LAB 覆盖的规则。

不得因为“LAB 是实验态”“LAB 不是 Stable”“Stable 更稳”等理由，在没有真实故障证据时预防性改用 v1.5.4。

> “LAB”描述的是发布治理状态，不表示该 Runtime 不得承担真实办公任务。

### 1.2 Stable 只作为故障回退

只有出现以下任一情况时，才允许回退 Stable：

1. Runtime deployment state 为 `DRIFTED`、`UNTRACKED` 或 `STALE`；
2. LAB overlay、必要规则或运行资源无法加载；
3. 已有真实任务证据表明当前 LAB 导致任务无法继续；
4. 已有真实任务证据表明当前 LAB 造成明显质量回归，且不能在不影响当前交付的前提下定向修复；
5. 用户明确要求改用 Stable。

普通执行偏差、一次工具失败、可定向修复的局部问题，不能自动解释为“LAB 不稳定”并触发回退。

### 1.3 回退必须是显式状态切换

回退 Stable 时，必须实际切换并核验 Runtime 身份，使状态重新满足：

- `channel=stable`
- `source_ref=main`
- `VERSION` 为当前确认的 Stable 版本
- deployment state 为 `SYNCED`

不得在 Runtime 仍为 LAB 时，只在推理或文字上“按 Stable 规则执行”并声称已经回退。

### 1.4 禁止 LAB / Stable 双跑

默认不得让同一任务同时跑 LAB 和 Stable 再择优，也不得为了保险重复生成两套成品。

LAB 正常完成则直接交付；只有触发明确回退条件时，才停止 LAB 路径并切换 Stable 继续当前任务。

## 2. Workspace 任务目录唯一命名

### 2.1 默认根目录

用户未另行指定任务目录时，本机文件型任务统一使用：

`/Users/macbook/ChatGPT/workspace/`

不得把普通任务直接创建在 `/Users/macbook/ChatGPT/` 根目录或其他临时根目录。

### 2.2 新任务目录格式

新建任务目录统一使用：

`YYYY-MM-DD_主题/`

规则：

- 日期必须使用带连字符的 `YYYY-MM-DD`；
- “主题”使用能识别任务对象的简短名称；
- 禁止新建 `YYYYMMDD`、`YYYYMMDD_主题` 等无连字符格式；
- 禁止仅以日期创建普通任务目录，如 `2026-09-21/`；
- 只有用户明确要求“按天汇总多个任务”时，才允许纯日期目录作为上层汇总容器。

示例：

`/Users/macbook/ChatGPT/workspace/2026-09-21_海勤工程纪检监察/`

### 2.3 同一任务持续复用原目录

同一任务的继续修改、补充材料、v2/v3 修订、定向返工和复核，必须继续使用原任务目录，不因日期变化、文件版本变化或再次进入 Work 而新建第二个任务根。

文件版本只体现在正式成品文件名中，不通过重复新建任务目录表达版本。

对于 LAB.3 之前已经存在的旧格式目录：

- 不为“统一格式”自动批量改名；
- 同一在办任务继续使用其已经锁定的原任务目录；
- 历史目录清理属于独立维护事项，未经用户明确授权不得顺带执行。

### 2.4 任务目录内部结构

文件型任务继续使用现有最小三分区：

- `00_原稿/`：真实输入原稿；
- `work/`：必要过程、审核和机械证据；
- `outputs/`：仅最终交付成品。

无对应内容的分区不为形式空建。

### 2.5 正式成品命名保持不变

正式成品继续沿用现行 Office Delivery 规则：

`YYYY-MM-DD_文种_主题_vN.ext`

用户明确指定文件名时，用户指定优先。

LAB.3 不修改正式成品命名规则，只统一 workspace 任务目录命名。

## 3. 实验验收

LAB.3 后续真实工作重点观察：

1. Work/Cabinet 在 Runtime 为 `lab + SYNCED` 时，是否实际使用 LAB，而不是因“实验态”自行绕回 Stable；
2. 未触发回退条件时，是否保持单一路径，不双跑 Stable；
3. 触发回退时，是否先完成真实 Runtime channel 切换和核验，再继续任务；
4. 新任务是否统一创建为 `YYYY-MM-DD_主题`；
5. 是否停止新建 `YYYYMMDD`、`YYYYMMDD_主题` 和普通纯日期任务目录；
6. 同一任务的 v2/v3 是否继续复用原任务目录；
7. 正式成品文件命名是否继续保持 `YYYY-MM-DD_文种_主题_vN.ext`；
8. 普通非 PPT 任务、PPT 数字基座和 v1.5.5-lab.2 的部署身份机制是否无回归。

结论仍只允许 `KEEP`、`OBSERVE`、`REVERT`。只有真实任务证明两项问题稳定消失，才考虑把对应机制带入未来正式 v1.5.5。
