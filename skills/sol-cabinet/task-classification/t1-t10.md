# Task Classification：审核与安全门槛

面向用户的启动级别只允许 T1-T4，及其预计时间与执行预算，定义见 T0 Executive Router。本文件保留的 1–10 数值只用于原有独立审核、安全门和任务画像兼容，不能作为第二套启动级别、向用户展示、扩时或增派执行者。

旧 T1-T10 数值表示审核和安全门槛，不表示执行团队人数。符合 Intake T1 且无敏感、高风险、外部事实、正式发布或显式独立审核要求时，以主代理和一次联合质量自检执行；办公文件格式本身不得单独触发多代理 Review。分类辅助见 `scripts/classify_task.py`；主代理仍须判断实际语义。

| 等级 | 任务信号 | 验收要求 |
|---|---|---|
| T1-T2 | 一句、一段、局部已知字段等低风险微改；或单输入→单输出、无正文改写与新增事实的确定性文件转换／局部排版 | 主代理精准处理并一次必要自检；原稿保护仍适用 |
| T3 | 单文件理解、短材料结构处理或显式审阅 | 按风险；显式独立审核不能省略 |
| T4-T6 | 正式成品、多源事实或明显复杂分工 | 至少一名未承担最终写入的独立审核者 |
| T7-T8 | 重要正式材料、高风险或大量关联材料 | 至少两条不同维度的独立判断路径 |
| T9-T10 | 项目级、系统建设或已授权长期运行 | 按当前阶段核验、交付并停止；多轮只复验变化与未决项 |

## 分类与资源分离

- 六轴（范围、推理、证据、交付、风险、持续性）只确定认知与核验需求；脚本保留风险门槛，不生成固定角色套餐。
- `professional_roles` 为旧输入兼容的复杂度信号，不是实际 Agent 数；新任务不靠填写人数抬级。
- 向正式方案新增来自材料的制度、审批、职责或协作规范，至少 T4；即使只改几段也不是低风险微改，画像标记 `formal_normative_additions=true`。
- 文件格式决定底层工具，不自动决定任务等级。范围明确的单文件局部编辑，或单输入→单输出、目标格式明确、无新增事实／正文改写／复杂模板迁移／批量耦合／高风险的确定性转换与局部排版，可以走 T1-T2 快车道；正式发布、事实核查、敏感事项与高风险不因此降档。
- `agents.minimum` 是含主代理的独立验收下限，`maximum=null` 表示无按等级设置的团队上限；它们不代替当前平台槽位限制。
- 主代理先识别具体独立读集或输出，将数量写入 `independent_work_units`。仅 `parallel_benefit=positive` 才规划额外执行代理；未知收益不扩派，工作留给主代理，不省略必要任务。
- `additional_execution_agent_budget` 仅限制本任务可选执行代理数量，必要独立审核另计，`available_subagent_slots` 是本轮平台观测，两者均可未知；未提供额度时不查询、不杜撰。不能把此字段当作全部子代理额度；若用户总预算不足以完成必要审核，停止并说明，不删审核或擅超总预算；无可用槽位时等待或说明未完成，不能自审冒充。
- “要快／全力”只表达偏好。速度收益来自真实独立任务、减少读取、减少无收益串行 Gate 和缩短关键路径；不凭偏好增加范围、任务等级或角色，也不以降低质量门槛换时间。

## 安全与阶段

关键材料不足或隔离未确认时保留 BLOCKED。敏感资料拒绝外部工具与持久上下文；风险与任务大小正交。

`stage_complete=true` 只用于完成已获验收的当前阶段后停止。脚本不证明成果通过，也不替代审核；即使下一阶段已授权，仍须新建范围合同并重新定级，不沿旧合同自动续作。

输入按 [Task Profile](../templates/task-profile.json)；输出总人数含 Final Lead，执行实例、审核角色和实际并发分别记录。禁止把逻辑角色表当作实际创建的代理数量。
