# 完工小结

文件型任务在成功交付前必须给用户一段简洁完工小结；纯分析任务也应有明确结果收口。不得只回复“已完成”。

## 必填内容

- **完成内容**：本次实际完成了什么。
- **实际成品**：逐项列出最终交付物；文件任务写真实文件名与路径／可下载位置。
- **目标目录核对**：该进的成品是否全部在位；最终目录是否仅含允许交付的成品和用户明确附件。
- **原稿保护**：已完成／不适用／未完成；有原稿时说明原件未覆盖状态。
- **关键核验**：内容、结构、公式、哈希、可打开性、视觉核验等本次真正执行过的项目；未执行的不得写成已通过。
- **未完成／限制**：无则写“无”；有则明确 PARTIAL／BLOCKED 及最小影响。
- **总耗时**：有可靠起止时间则写真实墙钟；没有可靠时间则明确“无法精确核实总耗时”，不编造秒数。
- **失误与处置**：仅本次有实质失误时写一句，否则省略。
- **进化状态**：完工前必须执行一次 Evolution Checkpoint，并按下文只显示一行状态；不得省略，也不得用长篇反思替代。

## 文件型任务附加对账

成功前必须确认：

1. 预期成品清单与实际成品逐项对应；
2. 用户指定格式、版本、命名和目标文件夹均满足；
3. `outputs/` 或用户指定最终目录没有混入过程稿、审核 JSON、日志、测试件、缓存、锁文件、临时转换件或其他无关产物；
4. `00_原稿/`、`work/`、`outputs/` 或用户指定目录各自内容符合职责；
5. 如果宿主限制导致无法实际整理目录，必须明确说明未完成，不能虚称归档完成。

## 兼容字段

需要更详细交接时可按下列字段展开，但不为形式机械堆字：

- 输出路径：
- 改动范围：
- 原稿目录：
- 原稿数量：
- 原稿清单：
- SHA-256 核验：通过／失败／未执行／不适用
- 原文件未覆盖：是／未验证／不适用
- 视觉渲染核验：已完成／未完成／不适用
- 归档与临时留存：实际状态；延后原因／必要留存

## Evolution Checkpoint 状态行（LAB.4）

每次 Cabinet 任务完工小结最后必须显示且只显示一行进化状态：

- `进化：CLEAN`：Checkpoint 已执行，本次未发现需记录的系统性问题；不触发维护读取、incident、回归或 EVO。
- `进化：RECORDED｜N项`：发现 N 项真实问题且已安全记录；只表示入队，未表示已修复。
- `进化：PENDING｜N项`：发现 N 项真实问题，但当前环境／证据／门禁未完成安全记录；不得声称后台会自动补录。
- `进化：EVO-YYYYMMDD-HHMMSS｜改进内容｜质量↑ / 速度↑｜回归通过`：仅真实正式晋升成功时使用；只写有证据的提升维度。

状态行不得包含业务正文、姓名、单位、附件名、业务路径或其他敏感细节。除用户明确要求外，不再展开第二段“自我进化报告”。

维护提醒仅使用本任务已知且可核实的既有事故／候选状态，在现有小结按需附一行；不新增扫描、日志块、流程或定时任务。满足以下任一条件才显示：

- high-impact 真实事故仍待处理（现有字段 `impact=high`）。
- 同类真实事故已达到既定重复阈值（两个独立任务），且已形成待处理候选；只有 hits 达标不显示。
- 存在 `pending-approval` 候选，或已形成候选因 Work→本机写回限制等待 Codex 维护。

按待办理事项去重计数，同一事故及其候选只计一项；已晋升、已关闭或已撤销事项不计入。最高级别沿用已有权限判断（approve 高于 auto）；尚无判断写“待判定”，不得为提醒自行授予或推断权限。格式：`维护：待进化 N 项｜最高级别：approve / auto / 待判定｜建议：交给 Codex`，级别只显示实际适用值。

未满足条件不显示任何维护提醒，也不显示“0 项”；普通 observation、首次低影响事故、hits 日志和内部分析均不展示。已自动完成并正式晋升的事项仍只按上述 EVO 规则显示；若另有符合条件的待办，可同时保留一行维护提醒。提醒只表示需要交棒，不触发维护、批准或晋升。
